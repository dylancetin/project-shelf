# Project Panel implementation contract

Bun + bun:sqlite backend, React + Vite UI. Default public port **4958**. All API routes relative to same origin; JSON. Errors `{error: string}` with appropriate status. Shared types in `shared/types.ts` are authoritative. Parent owns root package/config/build setup; frontend agent owns `src/`; backend agent owns `server/` and `tests/`.

Mutation origin checks accept the request's own origin, configured Settings → Network hostnames on the panel's port (HTTP/HTTPS) or standard HTTPS (443), and the exact public origin `https://panel.tail750ac6.ts.net`. Explicitly trusted origins may differ from the backend URL behind a TLS-terminating proxy. Settings changes apply immediately and persist normally. Unlisted origins, arbitrary service ports, null/malformed/extension origins, and same-site/cross-site Fetch Metadata without a trusted Origin remain rejected; requests without browser origin/metadata headers remain usable by CLIs. Imported service URLs and per-entry hostname overrides are not an origin allowlist. No CORS or forwarded-header trust is added.

## API
- GET /api/projects -> `{projects: Project[]}`
- POST /api/projects/reorder body `{kind:'project'|'service',ids:string[],previousIds:string[]}` -> `{projects:Project[]}`. Both lists must cover the complete kind, including hidden entries; `previousIds` must equal the current order. Invalid payloads return 400; missing/duplicate/foreign IDs or stale drafts return 409 without writing. Order is saved independently per kind in SQLite preferences and returned by GET; legacy unsorted entries default to name order, new registrations append after saved entries. Existing registrations, URLs, and runtime are unchanged.
- POST /api/projects -> `{project: Project}` body partial project fields, name and kind required. Registers existing directory or service URL.
- PATCH /api/projects/:id -> `{project: Project}` body partial persisted fields.
- Project `logo` accepts an empty string (automatic icon/monogram), a relative project image path, or an absolute HTTP(S) image URL without embedded credentials. Remote logos load directly in the browser without a referrer and fall back to a monogram on failure; the server never fetches or proxies them. Local images retain the confined `/logo` endpoint.
- Project `hidden` is a persisted boolean, defaulting to false for new and existing registrations. PATCH `{hidden:true}` hides an entry on Home and normal Manage collections; `{hidden:false}` restores it. GET still includes hidden entries for the `#manage/hidden` collection. Rescans retain visibility; hiding does not delete files or stop managed processes.
- DELETE /api/projects/:id -> `{ok:true}` removes registration only, stops managed process.
- POST /api/projects/:id/start body `{mode:'dev'|'prod'|'build'}` -> `{project: Project}`. Prod performs build then run. Build runs build only.
- POST /api/projects/:id/launch body `{}` -> `{project: Project}`. Starts development or reuses its active command, then waits up to 45 seconds for an HTTP response below 500 from the local configured port/address. Probes stay on loopback and do not follow redirects. Services and active build/production/stopping commands are rejected. Failed/stopped startup returns 409; readiness timeout returns 504 without stopping the process. Stop and deletion remain available while waiting. Navigation uses the returned project’s preferred hostname and full URL. Home clicks/search Enter and Manage/details Open all use this operation; service navigation stays direct.
- POST /api/projects/:id/stop -> `{project: Project}`
- GET /api/projects/:id/logs -> `{logs: LogLine[]}` bounded recent output; frontend polls when detail open.
- POST /api/projects/:id/duplicate body `{name:string,directory?:string,copyFiles:boolean}` -> `{project:Project}`. With copyFiles true copies source excluding .git, node_modules, generated/cache folders, never overwrites existing destination. false duplicates configuration.
- GET /api/projects/:id/logos -> `{logos:LogoFile[]}` candidates within project only.
- GET /api/projects/:id/logo?path=relative-file -> image response, restricted to images inside directory.
- GET /api/settings -> `{settings:Settings}`
- PATCH /api/settings body partial settings -> `{settings:Settings}`. `defaultSearchEngine` accepts `duckduckgo` (the default, including older saved settings), `google`, `bing`, or `brave`. The choice persists without changing project metadata or other preferences.
- GET/HEAD /search?q=... -> uncached 302 to the matching bang destination or saved default search engine for plain queries/unknown bangs. Empty queries return Home. No project commands are started.
- GET/HEAD /opensearch.xml -> browser search discovery using the current Shelf origin and saved engine. Home advertises this descriptor; the browser search template is `/search?q=%s`.
- POST /api/scan -> ScanResult. Idempotent, does not overwrite user edits or remove existing registrations. Within discovered projects, skips example/sample/demo and test/fixture directories (including testdata); nested apps/packages remain discoverable. Explicit scan roots opt into otherwise-skipped example/fixture trees. These scan-only exclusions do not affect file duplication.
- POST /api/bookmarks/import body `{html:string,localOnly?:boolean}` -> `{added:number,skipped:number}`. Default localOnly true. Import local docker/service bookmarks, dedupe URLs.
- GET /api/health -> `{ok:true}`
- GET /api/extension/bridge -> an inert, no-store HTML document with no scripts or message handler. Its CSP permits framing only by extension origins. The native new-tab extension injects its own host-authorized isolated content script here so API fetches retain their normal same-origin checks. This endpoint grants no API permission; direct extension-origin mutations remain forbidden.

## Behaviors
Defaults roots: /home/taytay/.t3/projects, /home/taytay/.t3-nightly/projects, /home/taytay/workspace. Hostnames: 192.168.1.50, beelinkk, beelinkk.tail750ac6.ts.net, 100.119.176.63. Per-entry hostname is empty for original URL; nonempty replaces hostname only, preserving port/protocol/path/query/hash. Project URLs may default to http://localhost:<port>. Do not start actual user projects during implementation. On first launch scan roots and seed local services from `data/bookmarks.html` (parent will provide). SQLite ignored at data/panel.sqlite. Backend server entry `server/index.ts` exports/starts Bun server, serves `dist/` when built, with PORT env default 4958, HOST default 0.0.0.0. For dev backend uses API_PORT=4959 via PORT env, Vite public 4958 proxies /api.

UI: warm minimalist start page named “Project Shelf”. Home is a condensed, search-first launcher with one-click project/service links, suitable for a browser new tab. Management is a separate view retaining source filters, full project cards, start/stop controls, and editing. Sidebar is an on-demand overlay, closed by default on every viewport. Details sheet provides commands/logs/logo/edit/duplicate. Add project/service modal, directory scan feedback, bookmarks import, responsive/mobile and keyboard accessibility remain available. All controls use real API operations; no fake projects/stats. The default server hostname is `beelinkk`; direct server links use it while dedicated proxy subdomains retain their original hostnames.

Ordering uses a dedicated draft dialog with handle-only sortable rows, keyboard/touch support, up/down buttons, numbered positions, and explicit Save/Cancel. Polling never replaces its draft. Home honors the API order within its groups; Manage defaults to Shelf order. The extension optionally supplies a local browser-bookmark provider through `src/platform.ts`; the website never gets Chrome access. Bookmarks are read from the native tree and reordered only within a writable, non-root folder using actual Chrome moves. Browser bookmarks never enter the server database or project snapshots. Native bookmark/permission event listeners are removed on unmount. Chrome moves are checked for stale/concurrent edits, stop at failure, and refresh actual state rather than attempting a destructive rollback.

Home uses one responsive column grid, defaulting to Projects, Services, Favorites, then bookmark columns. A versioned browser-local layout stores stable column IDs and bookmark section membership; Arrange mode permits section grouping, column reordering, new/empty targets, keyboard moves, and column/position alternatives. These actions never change the native bookmark hierarchy or server registration order. Reconciliation preserves manual groups across expansion, native reordering, Compact/Grid changes, and temporary bookmark-access failures, appending new sections without repacking established groups. Search never writes its filtered layout. Cross-tab layout changes are deferred during dragging; conflicts cancel local layout drops. Reset restores automatic grouping.

Nested disclosures retain locally persisted open-folder IDs. Inline bookmark row drops reorder a complete native sibling permutation using drag-start previous IDs, preserving omitted folder slots in synthetic root-link sections. Projects and Services each remain a single Home column with no automatic continuation groups. Project/service row drops on Home and Manage save complete-kind permutations while preserving omitted hidden/favorite/unconfigured slots. Search/non-Shelf sorts disable item ordering; older in-flight polls cannot overwrite successful saves. Native moves are nontransactional and refresh actual state on failure.

Bookmark icons use saved blobs, the local Chrome `/_favicon/` database, bundled logos, or deterministic colored initials. Explicit Enable/Refresh requests an exact optional `https://icons.duckduckgo.com/*` grant (preserved across server settings changes), sends only eligible public hostnames to that provider, validates/decodes bounded raster responses into PNG, and caches them in extension-local IndexedDB. IPs, short/private/special-use/Tailscale names, credentials, and nonstandard ports are excluded. Reads/new tabs never contact the provider or bookmarked websites. The cache retains legacy origin entries alongside new page-specific Chrome and hostname-specific online keys, is bounded to 1,000 entries / 128 KiB per image, supports explicit clear, and works offline without current network permission. Generic placeholders are not presented as branded successes; persistence/acquisition failures remain actionable.
